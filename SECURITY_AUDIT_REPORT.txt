  [CRITICAL] VULN-01: Hardcoded JWT Secret Fallback
  --------------------------------------------------
  File:       server.ts (line 454)
  Severity:   CRITICAL
  Status:     FIXED ✅
  Details:    The JWT signing secret had a hardcoded fallback string:
              'a3f9d2c1e8b74605af319de27c64f8a1b952e0d47618c3f290ab5e86d41379fc'
              If JWT_SECRET env var was missing, all tokens would use this
              known value — allowing token forgery.
  Fix:        Replaced with crypto.randomBytes(64).toString('hex') to generate
              a cryptographically secure random secret at startup if env var
              is missing. Console warning added to alert operators.

  [CRITICAL] VULN-02: Hardcoded Admin Password Fallback
  -----------------------------------------------------
  File:       server.ts (line 477)
  Severity:   CRITICAL
  Status:     FIXED ✅
  Details:    The admin login had a hardcoded default password 'radha@123'.
              If ADMIN_PASSWORD env var was not set, anyone could log in
              as admin using this known password.
  Fix:        Replaced with crypto.randomBytes(20).toString('base64url') to
              generate a random password at startup if env var is missing.
              Warning logged to console. Operators MUST set ADMIN_PASSWORD.

  [HIGH] VULN-03: Weak OTP Generation (Math.random)
  -------------------------------------------------
  File:       server.ts (line 2472)
  Severity:   HIGH
  Status:     FIXED ✅
  Details:    OTP codes were generated using Math.random() which is NOT
              cryptographically secure. An attacker could predict OTP values
              by observing PRNG state.
  Fix:        Replaced with crypto.randomInt(1000, 10000) which uses the
              operating system's CSPRNG for secure OTP generation.

  [HIGH] VULN-04: CORS Wildcard on Missing Origin
  -----------------------------------------------
  File:       server.ts (line 551)
  Severity:   HIGH
  Status:     FIXED ✅
  Details:    When no Origin header was present, the server responded with
              'Access-Control-Allow-Origin: *', allowing any domain to make
              credentialed cross-origin requests.
  Fix:        Now uses the configured ALLOWED_ORIGIN instead of '*' when
              no origin header is present (same-origin / server-to-server).

  [MEDIUM] VULN-05: Unsanitized Order Number Parameters
  ------------------------------------------------------
  File:       server.ts (lines 3327, 3365, 3442)
  Severity:   MEDIUM
  Status:     FIXED ✅
  Details:    Admin order endpoints used req.params.orderNumber.trim()
              without input sanitization. While these are admin-only endpoints
              (protected by verifyAdminToken), defense-in-depth requires
              sanitizing all user input.
  Fix:        Replaced with sanitizeString(req.params.orderNumber, 30)
              which strips HTML tags, control characters, and enforces max
              length before .toUpperCase().

  [MEDIUM] VULN-06: npm Dependency Vulnerabilities
  ------------------------------------------------
  Package:    body-parser, dompurify, nanoid, postcss, protobufjs
  Severity:   MEDIUM
  Status:     FIXED ✅ (npm audit fix)
  Details:    5 known vulnerabilities found in dependencies:
    - body-parser: DoS via invalid limit value
    - dompurify: XSS via IN_PLACE hook removal
    - nanoid: non-secure generators can loop indefinitely
    - postcss: path traversal via sourceMappingURL
    - protobufjs: DoS via infinite loop in .proto parsing
  Fix:        Ran `npm audit fix` — all 5 vulnerabilities resolved.
              Post-audit: 0 vulnerabilities remaining.

  [LOW] VULN-07: .env.example Branding Mismatch
  ---------------------------------------------
  File:       .env.example
  Severity:   LOW
  Status:     FIXED ✅
  Details:    .env.example header still referenced "MERIS E-SHOP" instead
              of "RADHA FASHIONS", which could confuse operators.
  Fix:        Updated header to "RADHA FASHIONS".

  [LOW] VULN-08: Admin Config Written as Plaintext JSON
  ------------------------------------------------------
  File:       server.ts (writeAdminConfig function)
  Severity:   LOW (Informational)
  Status:     ACCEPTED (monitoring)
  Details:    Admin credentials are stored in admin_config.json on disk.
              Passwords are bcrypt-hashed (cost factor 12), which is secure.
              However, the file itself is not encrypted at rest.
  Note:       This is acceptable for Railway deployments (ephemeral disk).
              For persistent deployments, consider migrating entirely to
              Supabase admin_config table.

 SECTION 10: RECOMMENDATIONS FOR FURTHER HARDENING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. CSP 'unsafe-inline' and 'unsafe-eval'
     Priority: MEDIUM
     The CSP currently allows 'unsafe-inline' and 'unsafe-eval' for scripts
     (required by Vite dev/build). Consider using nonces or hashes in
     production for stricter CSP.

  2. CSRF Token Protection
     Priority: MEDIUM
     While SameSite=Lax cookies + Origin header checks provide good CSRF
     protection, adding explicit CSRF tokens for state-changing POST
     endpoints would add another layer of defense.

  3. Content-Length Limits on POST Bodies
     Priority: LOW
     Consider adding app.use(express.json({ limit: '1mb' })) globally to
     prevent large payload attacks on non-upload endpoints.

  4. IP-based Account Lockout
     Priority: LOW
     The current rate limiter limits by IP. Consider adding progressive
     lockout (e.g., 30 min lock after 10 failed login attempts per IP).

  5. Security Audit Logging
     Priority: LOW
     Consider logging all failed authentication attempts, payment
     signature mismatches, and rate limit triggers to a persistent
     log for incident response.

  6. Supabase RLS Policies
     Priority: MEDIUM
     Ensure Supabase Row Level Security (RLS) policies are configured
     on all tables so that the service role key cannot accidentally
     expose data if API endpoints have authorization bypass bugs.
